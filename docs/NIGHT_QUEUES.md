# Night queues

`fila_noturna --add 'priority|space|threads|directory|command'` queues lightweight computations under the configured project root. Dispatch uses the same admission lock, resource metrics and managed process sessions as `rodar_local`; smaller priority numbers start first. Jobs preserve independent IDs, logs and exit statuses, including duplicate command lines. No job starts under PAUSA or with insufficient resources.

`fila_prioridade_noite` is a separate queue for agents. Copy `night-priority.example.json` and set `NIGHT_PRIORITY_CONFIG` to its absolute path. Under its `state_dir`, create `night-priority/queue.json`: `[{"space":"sample-alpha","pane":"w2:p1"},{"space":"sample-beta","pane":"w3:p1"}]`. Configure `send_command` as an argv list for Orquestra's `enviar_space`, never this queue itself. Existing idle agents receive one authorized-work prompt at a time. Dispatch requires a fresh usage cache (milliseconds timestamp, fiveHourPercent), an open economy/cycle door and the configured night hours. The active agent must write `night-priority/<space>.feito`; elapsed time alone never starts another agent. `PAUSA` blocks new dispatch. `--status` inspects; `--dry-run` previews without sending or changing the queue. Two cron invocations cannot dispatch concurrently.

Install schedules manually; no service, cron, model call or remote computation is installed by these tools. A safe sender must return nonzero instead of queueing when the agent cannot accept immediate dispatch. Notifications should use a local router if an owner space also needs an alert; no fixed pane map or phone topic is included.
